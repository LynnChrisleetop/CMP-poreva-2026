# 1. 浏览器登录（人人都要会）

打开 [trisol.dp.tech](https://trisol.dp.tech) → ENTER CONSOLE → 跳转玻尔（Bohrium）登录页，点「**企业版登录**」（不要用微信 / 邮箱等个人版方式）→ 企业代码输 `dpt` → 点「飞书授权登录」。**不需要单独注册账号**，复用公司统一身份。

第一次登入之后，你会落在「模型」列表页。**左下角侧边栏底部**能看到自己的头像 + 名字 —— 看到就登录成了：

![登录成功后，模型列表页左下侧边栏底部显示头像 + 名字](https://feishu.cn/file/MsicboG4RopE4CxqUf8cwyjMnzd)

> **登录后的团队归属：**使用企业统一身份登录时，尚未属于任何团队的用户会被自动加入本组织的 `default` 团队；已有团队成员关系保持不变。要访问其他业务团队的资源，再按 [1 加入团队](https://dptechnology.feishu.cn/wiki/U1phwPadgiAYpwkL9OwcTEURnPc) 申请加入。若团队列表仍为空，先核对登录组织与身份，并联系管理员确认。

# 2. CLI 安装（按需）

CLI 是给两类人准备的：

- **Agent / CI / 脚本** —— 自动化场景，UI 跑不动
- **CLI 偏好者** —— 命令行比 UI 顺手的同学

一行命令装好：

```Bash
curl -fsSL https://trisol.dp.tech/install.sh | bash

```

脚本会按以下优先级选安装位置：

1. `/usr/local/bin`（如果可写，**优先**）
2. `$HOME/.local/bin`（前者不可写时退回；脚本会自动 `mkdir -p` 并提醒你把它加到 PATH）

装好之后验证：

```Bash
trisol version

```

会打印版本号 / commit / Go 版本 / 平台等基础信息，能正常输出就说明装好了。

> **以后想升级 CLI？** `trisol update` 会从平台拉最新二进制并替换当前安装。

# 3. CLI 登录

CLI 的交互登录只有 Vouch 一种(公司统一身份,和浏览器入口同一条链);机器场景(CI / 脚本 / Agent)不做交互登录,改为注入短期凭据。按场景选:

| 场景 | 凭据 | 怎么配 |
|-|-|-|
| **自然人日常**(交互) | Vouch 登录(浏览器 / device code) | `trisol login`,菜单里选 1 或 2 |
| **CI / 无人值守脚本** | 短期 Vouch JWT(CI mint 流程签发) | `export TRISOL_TOKEN=<jwt>` |
| **Job / headless 环境** | Vouch 委派凭据(自动刷新) | 只注入 `VOUCH_DELEGATED_TOKEN` |

## 3.1 交互登录(Vouch,推荐自然人用)

```Bash
trisol login

```

跑 `trisol login` 会出现一个二选一菜单:**1) Browser**(默认,自动打开浏览器,走和 UI 一样的玻尔企业版登录链:企业版登录 → 企业代码 `dpt` → 飞书授权);**2) Device code**(headless / 远程机器用,打印 URL + 验证码,在任意一台有浏览器的机器上完成同样的授权)。登录态写到共享的 `~/.vouch/state.json` —— 其他接入 Vouch 的公司 CLI 也读它,一次登录多处生效;访问令牌按需签发、自动刷新,后续 CLI 命令自动带上。想随时看当前登录状态,用 `trisol login --status`。

确认身份：

```Bash
trisol whoami

```

默认表格输出 4 行（label 是英文）：

```Plain Text
User:      张三 <zhangsan@example.com>
API URL:   https://trisol.dp.tech
Team:      ml-infra (team-xxx)
Auth:      vouch state ~/.vouch/state.json (issuer https://vouch.dp.tech/) (vouch)

```

加 `-o json` 拿到结构化字段，包括 `user / is_admin / teams / api_url / team / auth`。

退出:`trisol logout`。注意它会一并清掉共享的 Vouch 会话(`~/.vouch`)—— 同一台机器上其他用 Vouch 的 CLI 会一起被登出;`api_url` 等环境偏好保留,当前团队选择会被清掉。

## 3.2 自动化 / CI:注入短期凭据(没有 PAT 了)

<callout emoji="❗">
**PAT(Personal Access Token)已于 v0.6.0 整体移除。**旧的 `trp_` / `trp2_` token 现在一律被服务端拒绝(HTTP 410,错误码 `pat_removed`);CLI 也不再有 `trisol token` 命令,Profile 页的 Tokens 入口同步下线。手里还攥着 PAT 的脚本:按下面两种方式之一改造。
</callout>

**CI / 无人值守脚本** —— 用 CI mint 流程签发的**短期 Vouch JWT**,经环境变量注入(不落盘):

```Bash
export TRISOL_TOKEN=<短期 Vouch JWT>

```

CLI 发送前会校验 JWT 的签发方和 audience 是否属于当前环境;过期了就让 CI 重新签发再注入。`TRISOL_TOKEN` 优先级高于本机登录态,适合在 CI 里精确控制身份。

**Job / headless 环境**(没有浏览器、也不想要本地 session)—— 只注入委派凭据 `VOUCH_DELEGATED_TOKEN`,CLI 会基于它按需取令牌并自动刷新。

同一台机器要隔离多套登录态(比如 CI 多账号),把 `VOUCH_CONFIG_DIR` 指到一个独立目录即可。

如果环境里还残留旧的 `TRISOL_TOKEN=trp_...`,CLI 会直接报 `personal access tokens were removed in v0.6.0` —— 这不是网络问题:unset 掉,重新 `trisol login` 或换短期 JWT。

# 4. 配置文件与多环境

CLI 的配置在 `~/.trisol/config.yaml`，`install.sh` 装完就写好了（已经塞好 `api_url` 指向当前环境）。典型内容：

```YAML
api_url: https://trisol.dp.tech
current_team: ml-infra
output: table

```

## 切换当前团队

```Bash
trisol config use-team <team-name>

```

或单次覆盖：

```Bash
trisol -t <other-team> inference list

```

环境变量 `TRISOL_TEAM` 也能覆盖；优先级：`-t flag` > `TRISOL_TEAM` env > `config.current_team`。

## 多环境 / Profile

如果你既要用 prod 又要测自己平台开发的版本（极少数情况），可以配 profile：

```YAML
api_url: https://trisol.dp.tech
current_team: ml-infra
profiles:
  myDev:
    api_url: https://my-trisol-dev.dp.tech
    current_team: test-team

```

用 `-p` 切：

```Bash
trisol -p myDev inference list

```

> 普通用户应该一个 prod 走天下，不需要 profiles。

# 6. 常见问题

### `trisol: command not found`

检查 install.sh 的输出，看二进制到底装到哪儿了；多半是 `$HOME/.local/bin` 没在 PATH 里。

### `trisol login` 浏览器没弹出来

`trisol login` 的浏览器流依赖本机弹窗;SSH / 容器等没有浏览器的环境,在登录菜单里选 **2) Device code** —— 它会打印一个 URL 和验证码,拿到任意一台有浏览器的机器上完成授权即可。注意 `--no-input` 会禁止一切交互提示(`trisol login` 会直接报错);纯自动化环境不要做交互登录,改用 3.2 的注入凭据。

### `trisol whoami` 报 401

凭证过期或已失效,重跑 `trisol login` 即可(可先 `trisol login --status` 看当前状态)。如果你用的是 `TRISOL_TOKEN` 注入:短期 JWT 过期了就让 CI 重新签发;如果里面还是旧的 `trp_` PAT —— PAT 已于 v0.6.0 移除(见 3.2),unset 后重新登录。

### 我想看 CLI 究竟在调啥 API

所有命令加 `--trace`：会把每次 HTTP 请求的 method / path / status / 耗时打到 stderr，方便对账 / 排障。
